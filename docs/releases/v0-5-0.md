# Boundra v0.5.0

## Release Summary

Boundra v0.5.0 introduces a typed configuration authoring surface for TypeScript applications while keeping the native CLI configuration model deterministic and runtime-independent.

The new `boundra/config` export provides `BoundraConfig` and `defineConfig()`, giving editors and TypeScript projects a public, package-backed source of truth for the configuration fields currently supported by Boundra's Rust project model.

This release intentionally keeps native config discovery on `boundra.config.json`. The TypeScript helper is an authoring and inference surface rather than a new executable configuration format, so the CLI does not need to start a Node.js runtime to load project configuration.

## Highlights

- Added the public `boundra/config` package subpath.
- Added the `BoundraConfig` TypeScript type for currently supported project configuration.
- Added `defineConfig()` for typed configuration authoring with literal inference preserved.
- Added typed configuration for project roots, workspace paths, domain public APIs, boundary scan extensions, ignore paths, capability classification, and shared-layer capability policy.
- Kept unsupported or not-yet-consumed configuration fields out of the public TypeScript contract so editor support matches actual CLI behavior.
- Added dedicated config type and runtime tests.
- Extended clean-room package verification to install the packed npm tarball and import `defineConfig` from `boundra/config`.
- Added configuration authoring documentation and updated package and architecture documentation.

## Installation

Install or update Boundra on Node.js 20 or later:

```bash
pnpm add boundra@0.5.0 zod
pnpm exec boundra check-boundaries
```

TypeScript applications can import the new configuration authoring surface:

```ts
import { defineConfig, type BoundraConfig } from "boundra/config";

const config = defineConfig({
  paths: {
    apps: "apps",
    domains: "domains",
    packages: "packages",
    crates: "crates",
  },
  checkBoundaries: {
    capabilities: {
      external: {
        react: ["ui"],
        "node:*": ["runtime"],
      },
      packages: {
        db: ["database"],
      },
      apps: ["runtime"],
    },
    policy: {
      shared: {
        denyCapabilities: ["ui", "database", "runtime"],
      },
    },
  },
});

const typedConfig: BoundraConfig = config;
```

The native CLI continues to discover project configuration from `boundra.config.json`.

The native CLI can also be installed from the tagged Rust source:

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.5.0 boundra-cli
```

## Breaking Changes

None.

Existing `boundra.config.json` files, CLI commands, Vite integration, runtime APIs, error-view APIs, boundary diagnostics, and default BR-003 behavior remain compatible.

## Known Limitations

- `boundra.config.ts` is not a native CLI configuration format in this release. The CLI continues to load `boundra.config.json`.
- `defineConfig()` is an identity helper for TypeScript authoring and inference; filesystem-aware and project-aware validation remains owned by the native CLI.
- The public `BoundraConfig` type intentionally covers only configuration fields currently consumed by the Rust project model. Future configuration features will be added as their runtime behavior becomes supported.
- The TypeScript config surface does not change the native CLI's runtime requirements and does not cause the CLI to execute user TypeScript or JavaScript during configuration loading.
