# Boundra v0.2.0

## Release Summary

Boundra v0.2.0은 framework별 workspace 구조와 실제 domain dependency graph를
같은 아키텍처 계약으로 다루는 public preview 릴리즈입니다. SvelteKit 같은
사용자 지정 경로에서도 boundary rule이 일관되게 동작하고, 코드의 cross-domain
import와 manifest의 `dependsOn`이 서로 어긋나는 상태를 조기에 차단합니다.

## Highlights

- `paths.apps`, `paths.domains`, `paths.packages`가 모든 boundary 판정에
  일관되게 적용됩니다.
- `.svelte` 파일이 기본 검사 대상에 포함되고 Vite source update가 boundary
  diagnostics를 다시 실행합니다.
- 상대 경로 `tsconfig extends` chain, JSONC, `baseUrl`, child alias override를
  해석합니다.
- BR-006이 manifest에 선언되지 않은 cross-domain public API import를
  차단합니다.
- project load와 `add-dependency`가 순환 domain dependency를 차단합니다.

## Installation

Node.js 20 이상에서 설치하거나 업데이트합니다.

```bash
pnpm add boundra@0.2.0 zod
pnpm exec boundra check-boundaries
```

native archive 또는 Rust source 설치도 지원합니다.

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.2.0 boundra-cli
```

## Breaking Changes

- 다른 domain의 public API를 import하는 source domain은 대상 domain을
  `dependsOn`에 선언해야 합니다. 선언이 없으면 BR-006이 발생합니다.
- 순환 `dependsOn` graph는 project configuration error로 처리되며 CLI가
  exit code `2`를 반환합니다.

기존 cross-domain import는 아래 명령으로 명시적으로 선언할 수 있습니다.

```bash
pnpm exec boundra add-dependency <source-domain>/<target-domain>
```

## Known Limitations

- package 이름을 사용하는 `tsconfig extends`는 아직 Boundra가 해석하지
  않으며 TypeScript toolchain이 소유합니다. 상대 경로 extends만 지원합니다.
- Vite integration은 source update마다 전체 boundary scan을 실행하며 아직
  incremental cache를 사용하지 않습니다.
- npm CLI 최초 실행은 cache가 없으면 GitHub Release 접근과 Unix `tar` 또는
  Windows PowerShell이 필요합니다.
