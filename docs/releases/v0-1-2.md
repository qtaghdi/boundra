# Boundra v0.1.2

## Release Summary

Boundra v0.1.2는 첫 외부 CRUD 도그푸딩에서 확인한 설치, 경계, 오류,
반복 코드와 성능 측정의 빈틈을 보강한 public preview입니다. 이제 하나의
`boundra` npm 패키지로 runtime과 native CLI를 사용하고, 프로젝트 초기화부터
Vite 개발 오류 확인까지 이어지는 흐름을 제공합니다.

## Highlights

- `pnpm exec boundra init`으로 비파괴적인 workspace 초기화를 지원합니다.
- npm CLI launcher가 플랫폼별 Rust binary를 내려받고 SHA-256 checksum을
  검증한 뒤 versioned user cache에서 실행합니다.
- BR-005가 `apps/**`에서 domain internal path로 우회하는 import를 차단합니다.
- `BoundraRuntimeError`가 field path와 provider-neutral validation issue,
  안전한 `toJSON()`을 제공합니다.
- `boundra/vite`가 runtime contract와 boundary 오류를 development overlay로
  표시합니다.
- `createHttpTransport`와 `generate resource`가 HTTP 및 CRUD 계약 반복을
  줄입니다.
- 1천/1만 source file benchmark와 CI smoke gate로 CLI 성능 회귀를 추적합니다.

## Installation

Node.js 20 이상에서 설치합니다.

```bash
pnpm add boundra@0.1.2 zod
pnpm exec boundra init --name my-app
pnpm exec boundra create-domain tasks
pnpm exec boundra generate resource tasks/task
pnpm exec boundra check-boundaries
```

native archive 또는 Rust source 설치도 계속 지원합니다.

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.1.2 boundra-cli
```

## Breaking Changes

없습니다. v0.1.1 runtime 및 기존 route/query/mutation 계약 API와 호환되는
additive release입니다.

## Known Limitations

- npm CLI 최초 실행은 cache가 없으면 GitHub Release 접근과 Unix `tar` 또는
  Windows PowerShell이 필요합니다. controlled/offline 환경은
  `BOUNDRA_CLI_PATH`를 사용할 수 있습니다.
- Vite integration은 source update마다 전체 boundary scan을 실행하며 아직
  incremental cache를 사용하지 않습니다.
- `generate resource`의 domain field schema는 안전한 빈 객체로 시작하므로
  애플리케이션이 실제 field를 작성해야 합니다.
- `createHttpTransport`는 protocol client만 제공하며 server router adapter는
  애플리케이션 또는 framework integration이 소유합니다.
