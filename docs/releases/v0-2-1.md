# Boundra v0.2.1

## Release Summary

Boundra v0.2.1은 실제 Presence 애플리케이션의 dogfooding에서 확인된 취소 처리와
작은 도메인의 구조적 마찰을 개선한 패치 릴리스입니다. 호출별 취소 신호가 사용자
transport까지 전달되고, 공개 API 레이어가 하나뿐인 도메인은 경계 보호를 유지한 채
더 간결한 루트 구조를 사용할 수 있습니다.

## Highlights

- query와 mutation 호출에 선택적인 `BoundraCallOptions`를 전달할 수 있습니다.
- `AbortSignal`이 custom transport와 HTTP transport의 `fetch`까지 전파됩니다.
- 명시적으로 취소된 요청은 `RUNTIME-003`으로 변환하지 않고 원래 취소 오류를 유지합니다.
- 공개 API 레이어가 정확히 하나인 도메인은 `public.ts`와 구현 파일을 도메인 루트에
  둘 수 있습니다.
- compact layout의 루트 파일도 client/server/shared 경계 규칙을 그대로 적용받습니다.
- 생성되는 query, mutation, resource client adapter가 호출별 옵션을 전달합니다.

## Installation

Node.js 20 이상에서 설치하거나 업데이트합니다.

```bash
pnpm add boundra@0.2.1 zod
pnpm exec boundra check-boundaries
```

native archive 또는 Rust source 설치도 지원합니다.

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.2.1 boundra-cli
```

## Breaking Changes

없음. 기존 두 인자 query/mutation 호출과 표준 `client`, `server`, `shared` 디렉토리
구조는 그대로 지원됩니다.

## Known Limitations

- compact layout은 manifest의 `client`, `server`, `shared` 공개 API 중 정확히 하나만
  비어 있지 않을 때 사용할 수 있습니다.
- compact layer 추론은 도메인 루트의 직접 파일에만 적용됩니다. 테스트는 `tests/`
  디렉토리에 두고, 두 번째 런타임 레이어를 추가할 때는 명시적 레이어 디렉토리로
  마이그레이션해야 합니다.
- code generation은 계속 표준 `shared/contracts`와 레이어별 public API 구조를 생성합니다.
- npm CLI 최초 실행은 cache가 없으면 GitHub Release 접근과 Unix `tar` 또는 Windows
  PowerShell이 필요합니다.
