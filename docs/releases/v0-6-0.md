# Boundra v0.6.0

## Release Summary

Boundra v0.6.0 adds manifest-backed nested domain discovery and extends boundary
analysis to understand local aliases declared in the root `package.json#imports`
field.

Teams can now organize domains below grouping directories such as
`domains/commerce/order` without changing the domain's manifest identity.
Boundary checks, generation, dependency updates, graphing, and coverage reporting
all use the discovered physical domain root.

## Highlights

- Recursively discovers the configured domain manifest below `paths.domains`.
- Keeps the manifest `name` as the stable domain identity across directory moves.
- Adds `create-domain <name> --path <parent-path>` for nested scaffolding.
- Rejects duplicate manifest names with deterministic root information.
- Uses discovered roots for BR-001 through BR-006, generation, dependency updates,
  and analyzed-domain coverage.
- Supports exact and single-wildcard local string mappings from root
  `package.json#imports`.
- Prevents exact aliases from matching similarly prefixed imports accidentally.
- Rejects local package alias targets that escape the workspace.
- Rejects symlinked child paths during nested domain creation while allowing the
  configured `paths.domains` root itself to resolve canonically.

## Installation

Install or update Boundra on Node.js 20 or later:

```bash
pnpm add boundra@0.6.0 zod
pnpm exec boundra check-boundaries
```

Create a nested domain:

```bash
pnpm exec boundra create-domain order --path commerce
```

The native CLI can also be installed from the tagged Rust source:

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.6.0 boundra-cli
```

## Breaking Changes

Directories directly below `paths.domains` are no longer treated as domains when
they do not contain the configured manifest file. Domain discovery is now
manifest-backed at every nesting depth.

To migrate an implicit domain, add the configured manifest file to its root and
ensure its `name` matches the leaf directory name. Existing manifest-backed flat
domains continue to work unchanged.

## Known Limitations

- Conditional objects and arrays in `package.json#imports` remain owned by the
  Node.js runtime and are not resolved by the current static analyzer.
- Alias resolution validates Boundra architecture boundaries but does not prove
  that a deployment platform includes raw source files in its server artifact.
  Server deployments should retain an artifact-level smoke test.
- The manifest `name` must match the leaf domain directory name; grouping
  directories are organizational and do not become part of domain identity.
