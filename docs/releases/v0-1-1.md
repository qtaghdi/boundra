# Boundra v0.1.1

## Release Summary

Boundra v0.1.1 is the first usable public preview. TypeScript applications can use the schema-backed runtime from the `boundra` npm package, while the Rust-based CLI handles domain creation, contract code generation, boundary checks, and dependency graph inspection.

## Highlights

- Statically analyzes client/server/shared/cross-domain boundaries through BR-001 to BR-004.
- Provides `create-domain`, `add-dependency`, `generate route/query/mutation`, `check-boundaries`, and `graph-domains` CLI workflows.
- Generated contracts validate inputs and results at runtime through Zod schemas and the `boundra` runtime.
- Diagnostics include stable error codes, file and line context, fix suggestions, and JSON output.
- Verifies the npm runtime and native CLI artifacts for Linux, macOS Intel/Apple Silicon, and Windows through clean-room and platform CI.

## Installation

Install the TypeScript runtime and schema authoring dependency:

```bash
pnpm add boundra@0.1.1 zod
```

The CLI can be installed from the platform archive attached to this GitHub Release or directly from the Rust source:

```bash
cargo install --git https://github.com/qtaghdi/boundra --tag v0.1.1 boundra-cli
```

Verify the installation with:

```bash
boundra --version
boundra --help
```

## Breaking Changes

- The accidentally published `boundra@0.1.0` package is not supported.
- Import `boundra` instead of the pre-release `@boundra/runtime` path used by earlier documentation and generated code.

## Known Limitations

- The npm package provides the TypeScript runtime but does not yet bundle native CLI binaries.
- Generated Zod schemas start as safe empty objects and must be filled with the application's real domain fields.
- A `boundra init` command for bootstrapping an empty project is not available yet.

- BR-001 through BR-004 boundary checks and domain graph verification
